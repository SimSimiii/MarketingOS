## Incident de migration résolu

Le premier build publié (`84a76f3a-daaf-41e2-ba84-47cb11cde50d`, candidat `ce75d0c`) a terminé en échec dans `post_build`. Le premier appel du migrateur a duré 83 secondes et a appliqué les deux migrations. La commande AWS a attendu 60 secondes, puis a réessayé l'invocation, lançant une seconde migration concurrente qui a rencontré une contrainte de type PostgreSQL déjà créée.

Le correctif `91eb48b` donne 360 secondes au client, interdit son retry implicite (`AWS_MAX_ATTEMPTS=1`) et réserve une seule exécution concurrente au migrateur. Cette configuration a été vérifiée dans AWS. Une invocation de contrôle, puis le build final, ont chacun confirmé `ok: true`. Aucune suppression de table, aucun stamp forcé, aucun retour arrière des données.

Un avertissement de compatibilité `click` entre SAM CLI et les dépendances de tests reste dans les logs d'installation globale ; les builds ont abouti. Isoler aussi l'outil SAM des dépendances de tests serait une amélioration ultérieure du circuit CI.
